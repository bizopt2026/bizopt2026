# 올리기 중심 입력 (파일을 올리면 AI가 정리) 설계

- 작성일: 2026-11-19
- 상태: 사용자가 방향을 승인하고 진행을 지시함 ("제안대로 진행")
- 기준 문서: `2026-11-18-solution-box-design.md` (전체 설계). 이 문서는 그 위에 얹는 변경이다.

## 1. 목적

지금은 사용자가 솔루션을 손으로 등록한 뒤 자료를 붙이고, 활동 기록은 메모를 붙여 넣는다. 사용자가 원하는 것은 반대다. **자료, 녹취록, 사진 등 파일을 올리기만 하면 AI가 무슨 자료인지 판단해 알아서 정리**하는 것이다. 솔루션 등록이 대표적인 예이고, 다른 입력도 모두 같은 방식이어야 한다.

## 2. 목표 / 하지 않는 것 / 피해야 할 것

### 목표
- 사용자의 입력은 "파일 올리기 + (원하면) 한 줄 메모" 로 끝난다.
- AI가 올린 파일들을 읽고 **정리안**을 만든다: 새 솔루션 등록, 기존 솔루션에 자료 추가, 활동 기록 작성, 고객·파트너 등록.
- 사용자는 정리안을 보고 **버튼 한 번**으로 저장한다. 고치고 싶은 것만 고친다.
- 사진(명함, 화이트보드, 문서 촬영)을 읽는다.
- 나중에 음성 파일을 그대로 받을 수 있게 자리를 만들어 둔다.

### 하지 않는 것 (이번 범위 밖)
- 음성 파일 받아쓰기. 음성 파일은 올릴 수 있고 보관되지만, "아직 받아쓰기를 지원하지 않습니다. 글자로 풀어 올려 주세요" 로 안내한다.
- 사용자 확인 없이 자동 저장.
- 올린 파일을 근거로 기존 기록을 AI가 스스로 수정·삭제하는 것 (추가만 한다).
- 동영상.

### 피해야 할 것
- **AI가 잘못 분류한 것이 그대로 저장되는 것.** 정리안은 항상 초안이고, 항목마다 "왜 이렇게 정리했는지" 한 줄과 근거 파일을 보여 준다.
- **올린 파일이 사라지는 것.** AI가 실패하거나 사용자가 정리안을 버려도 원본은 남아 있고 다시 정리하거나 직접 등록할 수 있다.
- **같은 묶음을 두 번 저장해 중복이 생기는 것.**
- AI가 안 될 때 입력 길이 막히는 것. 직접 등록 화면은 그대로 남긴다.

## 3. 제약 조건

- 기존 구조를 그대로 쓴다: FastAPI + SQLite + Jinja2/HTMX, AI 대기열과 Claude CLI 실행기, 지식 폴더 사본.
- 새 의존성 없음. 이미지 크기 조정은 이미 설치돼 있는 Pillow(python-pptx 의존성)를 쓴다.
- 도구 분리 규칙 유지: 정리 작업은 파일 도구(`Read`/`Glob`/`Grep`)만 쓴다. 웹 도구 없음.
- 사진은 Claude CLI의 `Read` 도구가 이미지를 직접 볼 수 있다는 점에 기댄다. **이 동작은 실제 CLI로 돌려 확인해야 한다** (자동 테스트는 가짜 CLI를 쓰므로 확인하지 못한다).
- 파일 하나의 크기 제한은 기존 `max_upload_mb`(100MB). 한 번에 올리는 파일은 20개까지.
- 올린 파일은 신뢰할 수 없는 자료다. 프롬프트에서 구분하고 "지시가 아니라 자료" 라고 적는다.

## 4. 검토한 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 올리기 묶음 + 정리안 확인 (선택)** | 올린 파일을 "올리기 묶음"으로 보관 → AI가 정리안(여러 항목) 작성 → 사용자가 확인하고 한 번에 저장 | 기존 원칙(AI 결과는 초안)을 지키면서 입력을 가장 줄인다. 파일이 묶음에 남아 실패해도 잃지 않는다 |
| B. 올리자마자 자동 저장 | 확인 없이 AI가 바로 기록을 만든다 | 가장 빠르지만 잘못 분류된 기록이 쌓이고 중복이 생긴다. 전체 설계의 "피해야 할 것"과 충돌 |
| C. 화면마다 올리기 버튼 추가 | 솔루션 화면에서 올리면 솔루션, 활동 기록 화면에서 올리면 기록 | 사용자가 여전히 "어디에 올릴지"를 정해야 한다. 원하는 것은 그 판단을 AI가 하는 것 |

사용자가 A를 승인했다.

## 5. 사용 흐름

```
[올리기] 파일 여러 개 + 한 줄 메모(선택)
   ↓  (바로 저장됨: 올리기 묶음)
[AI 정리 중…]  보통 1분 안에
   ↓
[정리안 확인]  항목 카드 n개
   ├ 새 솔루션: 이름·한 줄 소개·설명·태그·파트너 + 붙일 자료
   ├ 기존 솔루션에 자료 추가: 어느 솔루션 + 붙일 자료
   ├ 활동 기록: 종류·일자·제목·정리본·후속 조치·수요 단서·연결
   ├ 고객 / 파트너 등록
   └ 정리하지 못한 파일 (이유)
   ↓  [이대로 저장]  (항목별로 빼거나 고칠 수 있음)
[저장 완료]  만들어진 기록으로 가는 링크
```

- 한 줄 메모는 의도를 알려 주는 용도다 ("신규 솔루션 후보", "대성물류 11/17 통화"). 없으면 AI가 내용으로 판단한다.
- 파일 하나에서 여러 항목이 나올 수 있다 (예: 미팅 녹취록 → 활동 기록 + 새 고객). 여러 파일이 한 항목으로 묶일 수도 있다 (소개서 + 스펙 → 솔루션 하나).
- 정리안이 마음에 들지 않으면 메모를 고쳐 "다시 정리" 하거나, 묶음을 "버리기" 한다. 버려도 파일은 보관 기간 동안 남는다.

## 6. 화면

- **올리기** (`/intake/new`): 상단 메뉴 맨 앞에 "올리기". 파일을 끌어다 놓는 큰 영역(또는 파일 선택), 한 줄 메모, "올리기" 버튼 하나. 홈 화면 맨 위에도 같은 영역을 둔다.
- **올리기 목록** (`/intake`): 묶음별 상태 — 정리 중 / 확인 대기 / 저장 완료 / 실패 / 버림. 홈에 "확인 대기 n건".
- **정리안 확인** (`/intake/{id}`): 올린 파일 목록(읽기 상태 포함), 항목 카드들. 카드마다 종류 배지, AI가 채운 내용(바로 고칠 수 있는 입력칸), "이렇게 정리한 이유" 한 줄, 붙는 파일, "이 항목 제외" 체크. 아래에 고정된 "이대로 저장".
- 기존 **직접 등록** 화면은 남긴다. 솔루션 목록과 활동 기록 목록의 주 버튼은 "올리기"로 가고, "직접 입력"은 보조 링크가 된다.

## 7. 데이터

| 항목 | 내용 |
|---|---|
| 올리기 묶음 (`Intake`) | 메모, 상태, 정리안(JSON), 저장 결과(JSON: 만들어진 기록 목록), AI 작업, 올린 사람, 시각 |
| 올린 파일 (`IntakeFile`) | 묶음, 원래 이름, 저장 이름, 종류(문서/사진/음성/기타), 읽기 상태, 크기, 저장 뒤 연결된 기록(종류와 번호) |

- 원본은 `uploads/intake/<묶음 번호>/` 에 보관한다.
- AI가 읽을 사본은 `data_dir/intake_work/<묶음 번호>/` 에 만든다: 문서는 추출한 글(`.md`), 사진은 긴 변을 2,000px 이하로 줄인 사본. 정리 작업은 이 폴더를 작업 폴더로 삼는다. 저장하거나 버리면 이 폴더는 지운다.
- 저장할 때:
  - 솔루션에 붙는 파일은 기존 자료 파일(`SolutionFile`)로 복사되어 지식 폴더에 들어간다.
  - 활동 기록에 쓰인 파일(녹취록, 사진)은 올린 파일에 그 기록이 연결되고, 활동 기록 상세에서 "원본 파일"로 내려받을 수 있다.
  - 녹취록 글 전체는 활동 기록의 원문이 된다.

## 8. AI 정리 작업

- 작업 종류 `intake_analyze`, 대화형 우선순위. 도구는 파일 도구만, 작업 폴더는 그 묶음의 `intake_work` 폴더.
- 프롬프트에 넣는 것: 사용자 메모, 파일 목록(번호·이름·종류), 등록된 솔루션·고객·사업·파트너 이름 목록, 오늘 날짜.
- 출력은 정해진 구조의 정리안(JSON). 항목 종류: `new_solution`, `add_to_solution`, `activity`, `new_customer`, `new_partner`, `unplaced`. 항목마다 근거 파일 번호와 이유 한 줄.
- 서버가 정리안을 검증·정리한다:
  - 없는 파일 번호, 없는 솔루션 번호는 뺀다. 남는 것이 없는 항목은 버린다.
  - 새로 등록하려는 이름이 이미 있으면(이름 정규화 비교) "기존 항목에 연결"로 바꾼다.
  - 어느 항목에도 쓰이지 않은 파일은 `unplaced` 로 모은다.
  - 활동 기록 항목은 기존 초안 정리 규칙(종류·날짜 보정, 이름 연결)을 그대로 쓴다.
- 구조가 맞지 않으면 한 번 다시 요청하고, 그래도 실패하면 실패로 표시한다. 실패해도 파일은 남고 "다시 정리" 와 "직접 등록" 을 할 수 있다.
- 자료에 없는 내용을 지어내지 않는다. 채울 수 없는 칸은 비워 둔다.

## 9. 음성 파일을 위한 자리

- 음성 파일(mp3, m4a, wav 등)은 지금도 올릴 수 있고 보관된다. 종류는 "음성", 읽기 상태는 "받아쓰기 미지원".
- 코드에 받아쓰기 연결 지점(`app/transcribe.py`)을 둔다: `available()` 과 `transcribe(path) -> 글`. 지금은 "없음" 구현 하나뿐이다.
- 설정에 `transcriber = "none"` 을 둔다. 나중에 로컬 받아쓰기 프로그램을 붙이면 이 값만 바꾸고, 음성 파일은 문서와 같은 길로 흘러간다.
- 받아쓰기 방식(로컬 프로그램 종류, 서버 PC 사양)은 그때 따로 정한다.

## 10. 구현자에게 맡기는 것

- 화면 배치의 세부, 끌어다 놓기 스크립트(스크립트 없이도 파일 선택으로 동작)
- 프롬프트 문구
- 이미지 축소 방식과 지원 확장자 목록
- 올리기 묶음의 보관 기간 정리 방식 (기본: 저장·버림 뒤 원본은 그대로 두고 작업 폴더만 지움)

## 11. 작성자가 정한 사항 (사용자 확인용)

1. 저장 전 확인은 유지하되 버튼 한 번으로 줄인다.
2. 한 번에 20개까지 올린다.
3. 사진은 Claude CLI가 직접 읽게 한다 (별도 글자 인식 프로그램 없음).
4. 기존 직접 등록 화면은 보조 경로로 남긴다.
5. AI는 기록을 추가만 하고, 기존 기록을 스스로 고치거나 지우지 않는다.
6. 음성 파일은 받아 두기만 하고 받아쓰기는 다음 단계로 미룬다.
